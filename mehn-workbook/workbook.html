Step 2 of 8

Your First Web Server

Turn your program into a web server that your browser can visit.

First

Install the tools (only once per project) 
> npm init -y
> npm install express express-handlebars mongoose

This creates package.json and a node_modules folder. Never edit node_modules; it holds the downloaded tools.

Update app.js

app.jsreplace whole file 
// STEP 2 — Your first web server
// Run it with:  node --watch app.js
// Then open:    http://localhost:3000

const express = require('express'); // load the Express library
const app = express();               // create our web app

// When someone visits "/" (the home page), send back a message
app.get('/', (req, res) => {
  res.send('Hello World! This is my first web server.');
});

// Start listening for visitors on port 3000
app.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});

Run it

Terminal 
> node --watch app.js

Then open http://localhost:3000 in your browser.

You should see

localhost:3000
What just happened?
  • require('express') loads the Express library you just installed.
  • app.get('/', ...) is a route: "when someone visits the home page, run this function".
  • req is the request (what the browser asked for). res is the response (what we send back).
  • app.listen(3000) starts the server on port 3000. localhost means "this computer".
  • --watch restarts the server every time you save. Press Ctrl + C to stop it.
Try this
  • Change the message, save, then refresh the browser.
  • Send some HTML: res.send('<h1>Hi!</h1>')

Step 3 of 8

Routes: One Address, One Page

A route = an address + what to send back. Different addresses show different pages.

Update app.js

app.jsreplace whole file 
// STEP 3 — Routes: different addresses show different pages
// Run it with:  node --watch app.js

const express = require('express');
const app = express();

// http://localhost:3000/
app.get('/', (req, res) => {
  res.send('<h1>Home</h1><p>Welcome to my site!</p>');
});

// http://localhost:3000/about
app.get('/about', (req, res) => {
  res.send('<h1>About</h1><p>This site was made with Express.</p>');
});

// http://localhost:3000/hello/Ada   (try your own name in the address!)
app.get('/hello/:name', (req, res) => {
  const name = req.params.name; // the part of the address after /hello/
  res.send('<h1>Hello, ' + name + '!</h1>');
});

// TRY THIS: add a route for /contact

app.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});

Run it

Terminal 
> node --watch app.js

Then open http://localhost:3000/about in your browser. (Already running with --watch? Just save and refresh.)

You should see

localhost:3000/
localhost:3000/about
localhost:3000/hello/Ada
What just happened?
  • Each app.get(...) is one route. The first part is the address; the second is what to do.
  • :name is a placeholder. Whatever you type there ends up in req.params.name.
  • Visit an address that has no route (like /pizza) and Express answers Cannot GET /pizza.
Try this
  • Add a /contact route that shows your email.
  • Visit /hello/ followed by your own name.
  • Make /hello/:name also say how many letters the name has. Hint: name.length

Step 4 of 8

Views with Handlebars

Writing HTML inside res.send gets messy. Handlebars keeps each page in its own file, with blanks to fill in.

Create / update 3 files

Create the folders exactly as shown: views, and layouts inside it. Names and spelling matter!

views/layouts/main.handlebarsnew file 
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>Message Wall</title>
  <style>
    body { font-family: sans-serif; max-width: 600px; margin: 40px auto; padding: 0 16px; }
    .message { background: #f2f2f2; padding: 12px; margin: 8px 0; border-radius: 8px; }
    input, textarea, button { display: block; width: 100%; margin: 6px 0; padding: 8px; font-size: 16px; box-sizing: border-box; }
    button { cursor: pointer; }
  </style>
</head>
<body>
  {{{body}}}
</body>
</html>
views/home.handlebarsnew file 
<h1>{{title}}</h1>
<p>Hello, {{name}}! This page was made with Handlebars.</p>
app.jsreplace whole file 
// STEP 4 — Handlebars: HTML pages with blanks we can fill in
// Run it with:  node --watch app.js

const express = require('express');
const { engine } = require('express-handlebars');
const app = express();

// Tell Express to use Handlebars for our pages (our "Views")
app.engine('handlebars', engine());
app.set('view engine', 'handlebars');

app.get('/', (req, res) => {
  // Show views/home.handlebars and fill in the blanks
  res.render('home', {
    title: 'My First Page',
    name: 'Ada' // <-- TRY THIS: change the name
  });
});

app.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});

Run it

Terminal 
> node --watch app.js

Then open http://localhost:3000 in your browser. (Already running with --watch? Just save and refresh.)

You should see

localhost:3000
What just happened?
  • views/layouts/main.handlebars is the frame shared by every page. {{{body}}} marks where each page goes.
  • res.render('home', {...}) shows views/home.handlebars and fills in the blanks.
  • {{title}} is replaced by the value of title. The names must match exactly.
Try this
  • Change name to your own name.
  • Add a new blank {{school}} to home.handlebars, then give it a value in res.render.
  • Change the font or background color in the <style> section of main.handlebars.

Step 5 of 8

Showing a List with {{#each}}

Real websites show lists: posts, products, messages. {{#each}} repeats some HTML once for every item.

Create / update 2 files

You can keep views/home.handlebars; it just isn't used anymore.

views/messages.handlebarsnew file 
<h1>Message Wall</h1>

{{#each messages}}
  <div class="message">
    <strong>{{name}}</strong>: {{text}}
  </div>
{{/each}}
app.jsreplace whole file

// Run it with:  node --watch app.js

const express = require('express');
const { engine } = require('express-handlebars');
const app = express();

app.engine('handlebars', engine());
app.set('view engine', 'handlebars');

// Our data: a list of messages
const messages = [
  { name: 'Ada', text: 'Hello, world!' },
  { name: 'Alan', text: 'Web development is fun.' },
  { name: 'Grace', text: 'I just built a website!' }
  // TRY THIS: add a message of your own
];

app.get('/', (req, res) => {
  res.render('messages', { messages: messages });
});

app.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});

Run it

Terminal 
> node --watch app.js

Then open http://localhost:3000 in your browser. (Already running with --watch? Just save and refresh.)

You should see

localhost:3000
What just happened?
  • [ ... ] is a list (an array). { name: ..., text: ... } is one item (an object).
  • {{#each messages}} ... {{/each}} repeats the HTML inside once per item.
  • Inside the loop, {{name}} and {{text}} belong to the current item.

Step 6 of 8

Split It into MVC

Same app, better organized. Each job gets its own folder: Model, View, Controller.

Create / update 3 files

models/message.jsnew file 
// MODEL — in charge of the DATA.
// Right now the data is just a list in memory.

const messages = [
  { name: 'Ada', text: 'Hello, world!' },
  { name: 'Alan', text: 'Web development is fun.' },
  { name: 'Grace', text: 'I just built a website!' }
];

async function getAll() {
  return messages;
}

module.exports = { getAll };
controllers/messageController.jsnew file 
// CONTROLLER — the middle-man.
// It asks the Model for data, then hands it to the View.

const Message = require('../models/message');

async function showMessages(req, res) {
  const messages = await Message.getAll();        // 1. ask the Model
  res.render('messages', { messages: messages }); // 2. give it to the View
}

module.exports = { showMessages };
app.jsreplace whole file 
// STEP 6 — Organizing our code with MVC
//   models/       -> the data          (Model)
//   views/        -> what users see    (View)
//   controllers/  -> connects the two  (Controller)
// Run it with:  node --watch app.js

const express = require('express');
const { engine } = require('express-handlebars');
const messageController = require('./controllers/messageController');

const app = express();
app.engine('handlebars', engine());
app.set('view engine', 'handlebars');

// ROUTE: when someone visits "/", let the controller handle it
app.get('/', messageController.showMessages);

app.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});

Run it

Terminal 
> node --watch app.js

Then open http://localhost:3000 in your browser. (Already running with --watch? Just save and refresh.)

You should see

The page looks exactly the same as Step 5. That's the point: the code is reorganized, not changed.

localhost:3000
What just happened?
  • Model (models/message.js) owns the data.
  • Controller (controllers/messageController.js) asks the model for data and hands it to the view.
  • View (views/messages.handlebars) is what the user sees. It didn't change at all.
  • module.exports shares functions with other files; require() imports them.
  • async / await means "wait for the answer". Our list answers instantly, but a database (Step 8) needs a moment.
Try this
  • Add a 4th message. Which file did you open? Only the Model!
  • Add a count() function to the model that returns messages.length, and show the number on the page.

Step 7 of 8

Add a Form

Let visitors post their own messages. A form sends data to the server with a POST request.

Create / update 4 files

views/messages.handlebarsreplace whole file 
<h1>Message Wall</h1>

<form action="/messages" method="POST">
  <input name="name" placeholder="Your name" required>
  <textarea name="text" placeholder="Your message" required></textarea>
  <button type="submit">Post</button>
</form>

{{#each messages}}
  <div class="message">
    <strong>{{name}}</strong>: {{text}}
  </div>
{{else}}
  <p>No messages yet. Be the first!</p>
{{/each}}
models/message.jsreplace whole file 
// MODEL — in charge of the DATA.
// The data is still a list in memory (it resets when the server restarts).

const messages = [
  { name: 'Ada', text: 'Hello, world!' }
];

async function getAll() {
  return messages;
}

async function add(name, text) {
  messages.push({ name: name, text: text });
}

module.exports = { getAll, add };
controllers/messageController.jsreplace whole file 
// CONTROLLER — the middle-man between the Model and the View.

const Message = require('../models/message');

// GET /  -> show all messages
async function showMessages(req, res) {
  const messages = await Message.getAll();
  res.render('messages', { messages: messages });
}

// POST /messages  -> save a new message, then go back to the wall
async function createMessage(req, res) {
  await Message.add(req.body.name, req.body.text);
  res.redirect('/');
}

module.exports = { showMessages, createMessage };
app.jsreplace whole file 
// STEP 7 — Adding a form so visitors can post messages
// Run it with:  node --watch app.js

const express = require('express');
const { engine } = require('express-handlebars');
const messageController = require('./controllers/messageController');

const app = express();
app.engine('handlebars', engine());
app.set('view engine', 'handlebars');

// Lets Express read the data sent by our form (req.body)
app.use(express.urlencoded({ extended: false }));

// ROUTES
app.get('/', messageController.showMessages);
app.post('/messages', messageController.createMessage);

app.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});

Run it

Terminal 
> node --watch app.js

Then open http://localhost:3000 in your browser. (Already running with --watch? Just save and refresh.)

You should see

localhost:3000
What just happened?
  • <form action="/messages" method="POST"> sends what you typed to the server at /messages.
  • express.urlencoded(...) lets Express read the form data into req.body.
  • createMessage asks the model to save the message, then res.redirect('/') sends the browser back to the wall.
  • required on an input stops the browser from sending an empty form.
Try this
  • Post a few messages.
  • Now restart the server (Ctrl + C, then node --watch app.js). Where did your messages go?

Step 8 of 8

Save to MongoDB

Our list forgets everything when the server restarts. MongoDB is a database that remembers, and only the Model has to change.

Change just one file

MongoDB must be running. Windows: it runs automatically after installing. Mac: run brew services start mongodb-community.

models/message.jsreplace whole file 
// MODEL — in charge of the DATA.
// Now the data lives in MongoDB, so it is saved even if the server restarts.
// This is the ONLY file that changed from Step 7!

const mongoose = require('mongoose');

// Connect to the MongoDB database running on your computer
mongoose.connect('mongodb://127.0.0.1:27017/messagewall')
  .then(() => console.log('Connected to MongoDB'))
  .catch((err) => console.log('Could not connect to MongoDB:', err.message));

// Describe what a message looks like
const Message = mongoose.model('Message', new mongoose.Schema({
  name: String,
  text: String
}));

async function getAll() {
  return Message.find().lean(); // .lean() gives Handlebars plain data
}

async function add(name, text) {
  await Message.create({ name: name, text: text });
}

module.exports = { getAll, add };

Run it

Terminal 
> node --watch app.js

Then open http://localhost:3000 in your browser. (Already running with --watch? Just save and refresh.)

You should see

Terminal
> node --watch app.js
Server running at http://localhost:3000
Connected to MongoDB
localhost:3000
What just happened?
  • mongoose.connect(...) connects to the database on your computer. messagewall is the database name.
  • A Schema describes what one message looks like.
  • Message.find() gets all messages; Message.create() saves a new one.
  • .lean() gives Handlebars plain data. Without it you get an Access has been denied error.
  • The Controller, View and app.js did not change. That is MVC paying off.
Try this
  • Post messages, restart the server: they're still there!
  • Open MongoDB Compass, connect, then open messagewall → messages to see your data.
  • Add a new field (like mood: String) to the schema, an input to the form, and pass it through the controller.

1. Add a Delete button

Each message gets a button that removes it from the database.

Show the solution
models/message.jsadd this function, and export it 
async function remove(id) {
  await Message.findByIdAndDelete(id);
}

module.exports = { getAll, add, remove };
controllers/messageController.jsadd this function, and export it 
async function deleteMessage(req, res) {
  await Message.remove(req.params.id);
  res.redirect('/');
}

module.exports = { showMessages, createMessage, deleteMessage };
app.jsadd this route 
app.post('/messages/:id/delete', messageController.deleteMessage);
views/messages.handlebarsadd inside the {{#each}} message box 
<form action="/messages/{{_id}}/delete" method="POST">
  <button type="submit">Delete</button>
</form>

Every MongoDB document has a unique _id. The route /messages/:id/delete tells the controller which one to remove.

2. Newest first, with the date

Show when each message was posted, newest at the top.

Show the solution
models/message.jsadd { timestamps: true } to the schema 
const Message = mongoose.model('Message', new mongoose.Schema({
  name: String,
  text: String
}, { timestamps: true }));
models/message.jssort newest first in getAll 
async function getAll() {
  return Message.find().sort({ createdAt: -1 }).lean();
}
views/messages.handlebarsadd inside the message box 
<small>{{createdAt}}</small>

timestamps: true makes MongoDB store createdAt automatically. -1 means "biggest (newest) first". Older messages posted before this change have no date.

Help

When Things Break

Errors are normal: every developer sees them daily. Read the first line of the error; it usually tells you what's wrong.

'node' is not recognized / command not foundNode.js isn't installed, or the terminal was open during install. Install Node.js, then close and reopen VS Code.
Cannot find module 'express'Run npm install express express-handlebars mongoose inside your project folder.
EADDRINUSE: address already in use :::3000Another server is already running. Find that terminal and press Ctrl + C.
Cannot GET /somethingThere is no route for that address. Check the spelling in app.get(...).
Failed to lookup view 'home'The file must be views/home.handlebars. Check the folder name and spelling.
req.body is undefinedAdd app.use(express.urlencoded({ extended: false })); above your routes.
ECONNREFUSED 127.0.0.1:27017MongoDB isn't running. Windows: open Services and start "MongoDB Server". Mac: brew services start mongodb-community.
Access has been denied to resolve the propertyAdd .lean() after Message.find() in the model.
My change doesn't show upSave the file (Ctrl + S), then refresh the browser. Started with plain node app.js? Restart it.

Words to know

Browser
The app you use to visit websites (Chrome, Edge, Safari).

Server
A program that waits for requests and sends back responses.

Request / Response
The browser asks (request); the server answers (response).

Route
An address (like /about) connected to the code that answers it.

Terminal
A window where you type commands instead of clicking.

npm
Node's tool for downloading libraries (like Express).

Template / View
An HTML file with blanks ({{...}}) that get filled with data.

Model
The part of the app that handles data (getting it, saving it).

Controller
The go-between: takes the request, asks the model, hands data to the view.

Database
Where data is stored permanently, so it survives restarts.
